# GammaLoop workspace-hack compatibility shim

This package is a minimal downstream replacement for GammaLoop's generated
`gammaloop-workspace-hack` crate. That crate is generated by Cargo Hakari to
unify dependency features and improve cache reuse inside the GammaLoop
workspace; it contains no runtime API. Some downstream-reachable GammaLoop
crates nevertheless depend on it, which otherwise pulls the full GammaLoop
workspace feature graph into `symbolica-community`.

The replacement retains GammaLoop's explicit `arrayvec/std` and
`indenter/std` anchors because those sit outside Hakari's generated section and
are required by the Vakint build. It omits only the generated workspace-wide
feature list.

## Patch scope

Cargo patches apply to a repository source, not to one revision within that
repository. The patch in the root `Cargo.toml` therefore replaces the Hakari
crate for every pinned `https://github.com/alphal00p/gammaloop` dependency.
That includes both the newer FeynKit pin and the older shared pin currently
used by Spynso, Idenso, and Vakint.

Those revisions intentionally remain separate to avoid upgrading the existing
community modules as part of the FeynKit integration. As a result, Cargo builds
two revision-distinct `linnet 0.17.0` crates. Their Rust types must not cross
the revision boundary; the exposed community APIs currently exchange shared
Symbolica objects instead.

## Why the minimal package is acceptable

The shim is safe for the currently pinned graph because the real crates declare
the features required by their runtime APIs directly, while the two handwritten
Vakint anchors above are preserved verbatim. Removing the generated feature
list changes compilation and cache unification, but does not replace runtime
code. CI checks the default and Python-stub Rust feature sets with the declared
Rust 1.89 minimum, builds and installs the wheel on Linux and macOS, checks
FeynKit/Spynso import order, and exercises the installed APIs and tutorials.

This conclusion applies only to the revisions pinned in the root manifest.
Review the dependency and feature graph whenever either GammaLoop pin changes.

## Removal condition

Remove this directory and the root `[patch]` entry once every
downstream-reachable GammaLoop crate has stopped depending on the generated
workspace-hack package, or once upstream provides a downstream-safe equivalent.
After removal, regenerate `Cargo.lock`, confirm the duplicate dependency graph
is understood, and rerun the locked default, stub-generation, wheel, API, and
notebook checks.
